# v0.1 검수 보고서

대상은 사용자가 첨부한 `Risulike RPG.js`(기존 9.1.4)입니다. 원본 파일은 수정하지 않았습니다. 전체 파일에 문법·정적 검사와 콘텐츠 참조 검사를 적용하고, 위험도가 높은 저장·전투 종료·초기화·휴식 연계를 수정했습니다. 전수 정적 검사와 콘텐츠 순회는 완료했으나 모든 게임 분기와 모든 조합의 플레이 검증 완료를 의미하지 않습니다.

## 확인하고 수정한 결함

| 영역 | 원인과 영향 | 수정/검증 |
|---|---|---|
| 자동저장 | await 이후 전역 player/gameState/슬롯을 다시 읽어 다른 게임 상태와 섞임 | 호출 시 스냅샷, 직렬 큐; 상태 즉시 삭제 및 동시 두 슬롯 저장 테스트 |
| v1 가져오기 | saveAll을 기다리지 않고 전역 상태를 null로 변경 | 저장 성공 대기 후 화면 초기화 |
| v2 가져오기 | 슬롯 범위 제한 없음, 후반 데이터 오류 전에 앞 슬롯을 기록 | 모든 슬롯 ID·필수 구조를 쓰기 전에 검증 |
| v2 가져오기 | 항상 1번 슬롯을 불러오는 불필요한 처리 | 입력에 포함된 슬롯만 저장, 메뉴에서 선택 |
| 저장 오류 | 오류를 삼켜 성공처럼 처리 | 성공/실패 반환과 저장 실패 토스트, 후속 저장 복구 |
| 사망 | 앞서 시작한 저장이 슬롯 삭제 뒤 다시 기록할 가능성 | 삭제도 같은 저장 큐에 배치 |
| 초기화 | 묘지 미리 로드하지 않음, 도감은 메인 세이브가 있어야 로드 | 첫 렌더 전에 전역 기록 로드 |
| 도감 | 반복 조우의 count 증가 후 저장 없음 | 증가도 저장 |
| 전설 인벤토리 | _selectedLegendSlot 미선언 | null 초기화; 전 직업 인벤토리 렌더 |
| 승리 연출 | 같은 적에 대한 반복 호출 및 다음 게임까지 남은 타이머 | pending 상태, 적·게임 객체 확인, 부활 시 잠금 해제 |
| 턴 입력 | 턴 유효성 검사 전에 궁극기 쿨다운 및 마비 처리 | 함수 진입에서 전투 상태 검증 |
| 휴식 | 카드 depth prompt 영구 수정, 캐릭터 변경 시 다른 카드에도 기록 가능 | 캐릭터 ID로 한정한 beforeRequest 문맥; 종료 시 해제 |
| 직업명 | 없는 CLASS_DEFS 참조로 영문 키 fallback | PLAYER_CLASSES 참조 |
| 초기화 API | registerButton Promise를 기다리지 않아 rejection을 catch하지 못함 | await 적용 |
| 리소스/표기 | 이미지 키 8개 중복, trueSight 아이콘의 잘린 WebP, 표시 버전 v9 잔존 | 실제 사용되던 마지막 이미지 유지, 손상 아이콘은 기존 대체 표시, 표시 0.1 통일 |

## 검증 범위

- 파일 전체: JavaScript 구문, 미정의 변수, 중복 객체 키, 도달 불가 코드, 잘못된 typeof 검사.
- 직업 16종: 생성, 실전 스탯 계산, 인벤토리·상태 표시, 시작 스킬 실행.
- 스킬 91개: 각 액션 호출 후 플레이어·적 HP의 유한 숫자 확인. 모든 확률 분기나 설명 대비 수치 일치를 입증하는 테스트는 아닙니다.
- 적 51종: 6개 난이도 × 10개 층 = 3,060개 생성 조합의 HP·AC 검사.
- 장비 196개: ID 중복, 시작 장비 및 패시브 참조 검사. 패시브 정의 117개.
- 저장 비동기 경합, v1/v2 가져오기, 불량 입력 선검증, 저장 실패 후 복구, 사망 삭제, 기록 초기 로드, 휴식 요청 범위/재시도 중복 방지.
- 내장 이미지 445개는 전부 디코딩 검사했습니다. 잘린 trueSight 이미지 1개는 빈 값으로 교체해 기존 대체 표시를 사용합니다. 실제 이미지 미술 품질을 육안 전수 검사한 것은 아닙니다.
- 21개 테스트 통과. 동일 테스트를 원본에 적용하면 8개 통과/13개 실패합니다. 버전 표기와 새 저장 성공 반환 계약 검사도 포함하므로 이를 13개 독립 결함 수로 해석하지 않습니다.

## 공식 API 확인

공식 upstream 저장소 `kwaroran/RisuAI`의 로컬 체크아웃 `454e5e207747399f43a4788f5f08ecd5aa291550`에서 확인했습니다.

- `src/ts/plugins/apiV3/v3.svelte.ts`: getArgument/setArgument는 해당 플러그인 realArg의 정확한 키를 사용합니다. 이름 접두사를 자동 보정하지 않으므로 기존 저장 키를 그대로 유지했습니다.
- `src/ts/plugins/apiV3/risuai.d.ts`: add/removeRisuReplacer, onUnload, registerButton, getCharacter 지원.
- `src/ts/process/request/request.ts`: beforeRequest의 두 번째 인자는 모델 모드이며 기본 채팅은 `model`입니다. 테스트도 이 값으로 검증합니다.

이 확인은 최신 upstream 온라인 버전이나 실제 브라우저 통합을 검증했다는 의미가 아닙니다. 코어/서버/라이브 DB는 변경하지 않았습니다.

## 남은 검증과 제한

- Chromium 실행은 `libpixman-1.so.0` 누락으로 차단되었습니다. 브라우저 테스트 스크립트는 준비했지만 실제 데스크톱·모바일 렌더 결과는 없습니다.
- 공식 웹에서 설치/업데이트, 권한 허용/거절, 휴식 연결의 실제 모델 응답, 장시간 전투를 확인해야 합니다.
- 저장 데이터는 여러 키로 나뉘므로 쓰기 중 연결이 끊기는 경우 전체 트랜잭션 원자성은 제공하지 않습니다. 동시 기기 편집의 충돌 해결도 별도 과제입니다.
- 가져오기의 기본 구조/슬롯 검사는 악성 저장 데이터 전체의 보안 검증이 아닙니다. 문자열을 HTML로 조합하는 화면이 많아 출처를 모르는 저장 코드의 안전성을 보증하지 않습니다.
- 일부 전투/연출 타이머는 전역 상태를 읽습니다. 이번에는 승리 지연 콜백을 보호했으며, 전체 타이머 수명주기 개편은 후속 과제입니다.
- 91개 스킬·117개 패시브의 모든 상호작용과 설명/밸런스 일치는 자동 호출 검사만으로 확정하지 않았습니다.
