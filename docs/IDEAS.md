# 신규 아이디어 · 구현 현황

아래 1~6번은 `cloud/ideas-v0.2` 브랜치에서 구현했습니다. 표시 버전(v0.1)과 저장 키는 바꾸지 않았고, 새 저장 필드는 없으면 기본값을 씁니다.
RisuAI 안에서 돌아가는 게임이라는 점(봇 카드·채팅·모델 응답과 붙어 있음)을 살리는 항목을 우선했습니다.

| 순서 | 아이디어 | 상태 | 사용자에게 생기는 변화 | 구현 내용 |
|---|---|---|---|---|
| 1 | 세이브 미리보기·복원 지점 | 구현됨 | 가져오기 전에 덮어쓸 슬롯과 캐릭터를 확인하고, 실수하면 되돌림 | 코드 붙여넣기 → 슬롯별 현재/새 요약 비교 → **교체하기**를 눌러야 저장. 교체 직전 슬롯(구형 코드는 이어하기, v2 코드는 업적·묘지·도감·별 상점 포함)을 키 `RISUlike RPG::importRestorePoint` 1개에 보관하고 슬롯 메뉴에서 2단계 확인 후 **되돌리기** |
| 2 | 봇 캐릭터 소환 | 구현됨 | 지금 대화 중인 봇이 던전의 동료나 특별 보스로 등장 | 방 선택 화면에서 런당 각 1회. 동료는 기존 리리스 임시 동료 수치(25%·최대HP 8%), 보스는 현재 층 보스 템플릿 능력치를 그대로 쓰고 이름만 입힘(엘리트 판정이라 층 진행 불변). 이미지는 `data:image/…;base64` 또는 `https://`일 때만 아이콘으로 쓰고 세이브에는 넣지 않음. 카드에 쓰지 않음. 캐릭터가 없거나 독립 실행이면 숨김 |
| 3 | 모험 일지 → 채팅 | 구현됨 | 사망·클리어 후 이번 런의 이야기를 봇 채팅에 이어서 쓸 수 있음 | `_journeyLog`와 이번 묘지 기록으로 요약문 생성. **일지 복사**(클립보드, 실패 시 선택 가능한 글상자) 또는 **다음 채팅에 첨부**(캐릭터 한정 beforeRequest, `model` 요청만, 마지막 user 앞 삽입, 1회 사용 후 해제) |
| 4 | 런 결과 카드 이미지 | 구현됨 | 클리어/사망 결과를 한 장의 이미지로 저장해 커뮤니티에 공유 | 직업 초상화·직업·난이도·층·처치·탐험·골드·주요 장비·사인을 540×720 canvas에 그려 PNG 생성. 화면에 항상 띄워 길게 눌러 저장할 수 있고, 다운로드 버튼은 iframe이 허용할 때만 동작. 외부 업로드 없음 |
| 5 | 동료 역할 선택 | 구현됨 | 리리스·헬레나의 행동을 플레이 스타일에 맞춰 선택 | 기본(기존과 동일)/공격/보호/탐색. 발동 확률 배수·효과 비율과 탐색 시 상자 방 가중치(×1.25)만 조정. 대사·합류 조건 유지. `gameState.allyRoles`에 저장, 없으면 기본 |
| 6 | 효과 줄이기·음량 설정 | 구현됨 | 모바일에서 흔들림·번쩍임과 소리를 조절 | 메인 메뉴에 효과(기본/약하게/끄기)와 음량 0~100. 저장값이 없고 prefers-reduced-motion이면 '약하게'. 기기별 전역 키 `RISUlike RPG::uiSettings`(safeLocalStorage) |

### 수치 표 (5번 동료 역할)

| 역할 | 리리스 발동 배수 | 리리스 딜 / 보호막 / 둘 다 | 헬레나 지원 확률 | 헬레나 회복 / 공격약 / 방어약 | 상자 방 가중치 |
|---|---|---|---|---|---|
| 기본 | ×1.00 | 33% / 33% / 34% | 30% | 60% / 25% / 15% | ×1 |
| 공격 | ×1.25 (최대 50%) | 55% / 10% / 35% | 36% | 30% / 55% / 15% | ×1 |
| 보호 | ×1.00 | 10% / 55% / 35% | 30% | 45% / 10% / 45% | ×1 |
| 탐색 | ×0.80 | 33% / 33% / 34% | 24% | 60% / 25% / 15% | 동료당 ×1.25 |

리리스 딜/보호막 비율은 퀘스트 동료(`lilith`)에만 적용됩니다. 임시 동료(`lilith_temp`)는 원래 딜만 하므로 발동 배수만 적용됩니다. 이 수치는 플레이 테스트로 조정한 값이 아니라 초기값입니다.

## 제외한 항목

이전 초안의 다음 항목은 비용 대비 효과가 낮아 뺐습니다.

- **전투 피해 명세**: 피해 계산이 91개 스킬 분기에 흩어져 있어 계측 비용이 크고, 대부분의 플레이어에게 필요한 정보가 아닙니다.
- **빌드 도감(추천)**: 장비가 무작위로 나오는 로그라이크라 추천을 봐도 얻을 수단이 없습니다. 기존 도감으로 충분합니다.
- **시드 도전**: `Math.random` 호출이 코드 전반에 퍼져 있어 교체 범위가 크고, 혼자 하는 채팅 플러그인에서 시드 공유 수요가 낮습니다.
- **짧은 원정(3층 모드)**: 별도 모드와 보상 분리를 유지하는 비용에 비해 기존 10층 런과 차별점이 작습니다.

## 구조 개선

데이터/저장/전투/화면을 소스 모듈로 분리하되, 설치 파일은 지금처럼 JS 하나로 빌드하는 방향이 적합합니다. 전투 타이머에 런·전투 ID를 부여하고 저장 포맷 버전을 명시하면 이후 기능 추가와 재현 테스트도 수월해집니다.
