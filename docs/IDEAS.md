# 신규 아이디어 · 제안 단계

다음 기능은 아직 구현하지 않았습니다. 저장 안정성과 검증을 먼저 확보한 뒤 추가하는 순서입니다.
RisuAI 안에서 돌아가는 게임이라는 점(봇 카드·채팅·모델 응답과 붙어 있음)을 살리는 항목을 우선했습니다.

| 순서 | 아이디어 | 사용자에게 생기는 변화 | 구현 방향 |
|---|---|---|---|
| 1 | 세이브 미리보기·복원 지점 | 가져오기 전에 덮어쓸 슬롯과 캐릭터를 확인하고, 실수하면 되돌림 | 슬롯별 요약 비교 후 명시적 교체, 교체 직전 슬롯 1개를 별도 키에 보관 |
| 2 | 봇 캐릭터 소환 | 지금 대화 중인 봇이 던전의 동료나 특별 보스로 등장 | `getCharacter()`의 이름·아이콘을 기존 동료/보스 틀에 입힘. 능력치는 기존 데이터를 재사용하고 카드에는 쓰지 않음 |
| 3 | 모험 일지 → 채팅 | 사망·클리어 후 이번 런의 이야기를 봇 채팅에 이어서 쓸 수 있음 | 기존 `_journeyLog`·묘지 기록으로 요약문 생성, 복사 또는 다음 요청 1회에만 문맥으로 첨부 |
| 4 | 런 결과 카드 이미지 | 클리어/사망 결과를 한 장의 이미지로 저장해 커뮤니티에 공유 | 직업·층·장비·처치 수를 canvas로 그려 PNG 다운로드. 외부 업로드 없음 |
| 5 | 동료 역할 선택 | 리리스·헬레나의 행동을 플레이 스타일에 맞춰 선택 | 공격/보호/탐색 역할에 따라 기존 발동 확률·효과 가중치만 조정, 대사와 합류 조건 유지 |
| 6 | 효과 줄이기·음량 설정 | 모바일에서 흔들림·번쩍임과 소리를 조절 | prefers-reduced-motion 기본 반영, 이펙트 끄기/약하게, 음량 0~100 |

## 제외한 항목

이전 초안의 다음 항목은 비용 대비 효과가 낮아 뺐습니다.

- **전투 피해 명세**: 피해 계산이 91개 스킬 분기에 흩어져 있어 계측 비용이 크고, 대부분의 플레이어에게 필요한 정보가 아닙니다.
- **빌드 도감(추천)**: 장비가 무작위로 나오는 로그라이크라 추천을 봐도 얻을 수단이 없습니다. 기존 도감으로 충분합니다.
- **시드 도전**: `Math.random` 호출이 코드 전반에 퍼져 있어 교체 범위가 크고, 혼자 하는 채팅 플러그인에서 시드 공유 수요가 낮습니다.
- **짧은 원정(3층 모드)**: 별도 모드와 보상 분리를 유지하는 비용에 비해 기존 10층 런과 차별점이 작습니다.

## 구조 개선

데이터/저장/전투/화면을 소스 모듈로 분리하되, 설치 파일은 지금처럼 JS 하나로 빌드하는 방향이 적합합니다. 전투 타이머에 런·전투 ID를 부여하고 저장 포맷 버전을 명시하면 이후 기능 추가와 재현 테스트도 수월해집니다.
